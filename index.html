Ask IT to deliver a working warehouse display—including a plan for secure Power BI access. As the report developer, you own report configuration, the display refresh mechanism, source/model refresh settings, and everyday freshness checks. IT provides the device platform and coordinates any administrator-only access.

An existing Raspberry Pi display is a useful starting point. Ask IT to inspect and reuse that supported setup where appropriate. A screen showing a webpage does not prove that private Power BI reports will stay signed in or display fresh data.

These are planning and operating documents. No Pi, TV, tenant, or Power BI report has been configured by creating these files. Your exact display platform, report URLs, account, licensing, and refresh requirements still need to be confirmed.

Secure access is shared work. You manage the reports and can grant access within your existing permissions. Tenant policies, capacity, licensing, and authentication automation need the relevant administrator. Ask IT to name that person during setup.

Agree on these settings before setup

  • First reports: OTD Dashboard and Warehouse Management; exact links and pages to be supplied.
  • Initial proposal: rotate every 60 seconds and reload the display every 5 minutes, subject to report performance and the selected player.
  • Separately agree how old the underlying data may be. A five-minute browser reload is not a five-minute source-data refresh.
  • Define whether occasional manual sign-in is acceptable. If it is not, require a supported solution with automatic token renewal and recovery.
  • Record who handles device faults, report/data problems, and access problems.
