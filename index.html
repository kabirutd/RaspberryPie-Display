I want the warehouse TV to show the OTD Dashboard and Warehouse Management reports throughout the day. IT will set up the Raspberry Pi, TV, network, and automatic startup. I’ll handle the reports, refresh mechanism, and rotation once the platform is ready.

There’s already another monitor running on a Raspberry Pi. I’ll ask IT to check that setup first and reuse the same approach if it fits.

Two things need to work: the reports need to stay accessible, and the numbers need to stay current. Reloading the browser helps with the display, but it doesn’t update the source data or prevent a Microsoft session from expiring.

These notes describe the planned setup. The final account, report links, refresh intervals, and support contacts will be recorded during the handoff.

Where do the scripts run?

The box is the computer; the TV shows its screen. Browser-refresh scripts run on the Raspberry Pi. Power BI data-refresh settings are configured separately in the Power BI service.

Settings to agree before we start

  • Reports: OTD Dashboard and Warehouse Management, with the exact pages and warehouse filters.
  • Rotation: start with 60 seconds per report.
  • Display reload: aim for five minutes if the chosen player supports independent refresh and rotation. The simple two-tab script reloads on each turn instead.
  • Data age: agree how current each report needs to be, then check whether the model and capacity can meet that requirement.
  • Sign-in: decide whether occasional manual sign-in is acceptable. If it isn’t, we’ll need a supported player or application that renews tokens automatically.
  • Support: record who handles hardware, network, account, and report issues.

The pages also open locally from index.html. Checkboxes aren’t saved between visits; I’ll keep the completed handoff in the IT ticket or print a copy.
