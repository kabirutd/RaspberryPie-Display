1. Confirm requirements and owners

  1. Collect exact OTD and Warehouse Management report links, target pages, site filters, and intended viewers.
  2. Agree operating hours, viewing distance, display dwell time, and maximum acceptable data age.
  3. I’ll handle the reports, refresh mechanism, rotation, and permissions within my access. IT will handle the device, network, and startup. The relevant administrators will handle restricted policies and licensing.
  4. Decide whether occasional manual sign-in is acceptable. Record its recovery procedure or select an unattended solution.
  5. Record the existing Pi’s hardware, OS, player, account method, configuration backup, and support history before changing it.

Proposed starting settings: 1080p output, 60 seconds per report, and five-minute browser reloads for a single report. These are adjustable proposals; data freshness must be agreed separately.

2. Install hardware and connect the TV

  • Raspberry Pi 5; 8 GB RAM is a practical recommendation for complex reports.
  • Official 27 W USB-C supply, active cooling, and a ventilated case.
  • Reliable high-endurance microSD storage or a suitable SSD.
  • Micro-HDMI-to-HDMI cable, TV/monitor, Ethernet, and a temporary keyboard/mouse.
  • Optional UPS and approved mounting/cable protection.
  1. Install cooling and storage with the Pi powered off.
  2. Connect HDMI to the TV, preferably HDMI0 on the Pi for the single display.
  3. Connect Ethernet and temporary input devices.
  4. Select the TV’s HDMI input, then power the Pi.
  5. Set 1920 × 1080 initially; adjust for readability and performance.
  6. Disable TV sleep timers and automatic shutoff. Enable return-on-power behavior if supported.

Raspberry Pi recommends the 27 W supply for Pi 5. Confirm local mounting and electrical requirements with IT. Hardware reference.

3. Install and configure Raspberry Pi OS

Commands in this guide run on the Pi’s Linux terminal, as its desktop user. They are not Windows PowerShell commands. The reference environment is current Raspberry Pi OS 64-bit with desktop, using Wayland/labwc.

  1. Use Raspberry Pi Imager on a separate computer.
  2. Select Raspberry Pi 5 and Raspberry Pi OS 64-bit with desktop, not Lite.
  3. Select the intended storage device carefully; imaging overwrites it.
  4. Set an approved local user, unique hostname such as warehouse-display-01, correct time zone, and network settings.
  5. If approved, enable SSH using a public key for IT remote support.
  6. Write the image, insert it into the Pi, and boot.
sudo apt update
sudo apt full-upgrade -y
sudo apt install -y chromium wtype
sudo reboot

Configure the desktop:

sudo raspi-config
  • System Options → Boot / Auto Login → Desktop Autologin.
  • Display Options → Screen Blanking → No.
  • Check locale/time zone and network/time synchronization.

Menu labels vary by release. Use the desktop Control Centre’s Display settings if appropriate. Autologin exposes the local session to anyone with physical access; IT should approve and secure the kiosk location. Configuration reference.

  1. Obtain approval for the identity/player and its session policy. Avoid placing an employee’s full work account on the TV without approval.

  1. Sign in normally, complete MFA, and use persistent sign-in only as permitted by policy.

5. Configure real data freshness

RefreshOwnerWhat it accomplishes
Browser reloadMe, using the agreed player/scriptsReloads the report using data available to Power BI. Does not import new source data.
Import-model refreshMe; administrators support infrastructureLoads updated source records into the semantic model.
Automatic page refreshMe / capacity administrator for restricted settingsRequeries supported data sources while the report page is displayed.

Import reports

  1. In the Power BI service, open workspace → semantic model → Settings.
  2. Configure source credentials and any required on-premises gateway.
  3. Set the refresh schedule for the required operating hours.
  4. Check Refresh history and confirm a known source change appears in the report.

Shared capacity allows up to eight scheduled refreshes daily; Premium scenarios support up to 48 scheduled time slots daily. Do not promise five-minute source freshness from five-minute browser reloads. Data refresh reference.

DirectQuery / supported automatic page refresh

  1. In Power BI Desktop, select each intended page and enable Page refresh in page formatting.
  2. Choose the interval, publish, and test the effective interval in the service.
  3. Confirm applicable capacity settings with the administrator. Shared-capacity automatic page refresh has a 30-minute minimum; dedicated capacity and PPU have their own applicable settings.

Import tables do not become live through automatic page refresh. If native page refresh meets the need, omit the browser refresh helper below to avoid unnecessary loading screens. Automatic page refresh reference.

I’ll add a visible “data as of” timestamp based on actual source/model freshness and label its time zone. A clock showing the current time doesn’t prove the numbers are current.

6. Configure the reference Chromium kiosk

I’ll configure and maintain the refresh helper once IT has set up the browser platform and handed over access. We’ll agree how the scripts start and how to recover the display. This example uses labwc startup, a persistent Chromium profile, and wtype to send reload keys. It can reopen a closed browser, but it won’t detect every frozen page or fix expired sign-in.

Before running commands: I’ll follow the access walkthrough. These commands belong in the Pi terminal under the kiosk desktop user. For the first graphical test I’ll use the TV desktop or screen sharing into that same session. SSH can edit files but does not automatically inherit the TV desktop’s graphical environment. The scripts below are examples to install; reading this page does not install them.

A. Create the launcher

mkdir -p "$HOME/bin" "$HOME/.config/labwc"
nano "$HOME/bin/warehouse-kiosk.sh"

Paste and replace the URL placeholder. Keep URLs quoted.

#!/usr/bin/env bash

REPORT_URL='PASTE_OTD_PAGE_URL_HERE'
PROFILE="$HOME/.config/warehouse-chromium"
PAUSE_FILE="$HOME/warehouse-maintenance"

# Only run one launcher and one browser for this profile.
exec 9>"$HOME/.config/warehouse-kiosk.lock"
flock -n 9 || exit 0

while true; do
    if [ -e "$PAUSE_FILE" ]; then
        sleep 5
        continue
    fi

    chromium \
      --user-data-dir="$PROFILE" \
      --kiosk \
      --no-first-run \
      --noerrdialogs \
      "$REPORT_URL"

    sleep 10
done

B. Create the optional five-minute reload helper

nano "$HOME/bin/warehouse-refresh.sh"
#!/usr/bin/env bash

REFRESH_SECONDS=300
PAUSE_FILE="$HOME/warehouse-maintenance"

exec 9>"$HOME/.config/warehouse-refresh.lock"
flock -n 9 || exit 0

while true; do
    sleep "$REFRESH_SECONDS"
    if [ ! -e "$PAUSE_FILE" ]; then
        wtype -M ctrl -k r -m ctrl
    fi
done

This sends Ctrl+R to the focused window. Keep the kiosk as the only active application and pause automation before maintenance or sign-in. Browser kiosk mode remains active across reloads; temporary report selections and Power BI’s own full-screen state may reset. Persist the target view in the report or a tested bookmark/URL.

C. Enable desktop startup

chmod +x "$HOME/bin/warehouse-kiosk.sh"
chmod +x "$HOME/bin/warehouse-refresh.sh"
nano "$HOME/.config/labwc/autostart"

Preserve existing contents. Append these lines once:

"$HOME/bin/warehouse-kiosk.sh" >>"$HOME/warehouse-kiosk.log" 2>&1 &
"$HOME/bin/warehouse-refresh.sh" >>"$HOME/warehouse-refresh.log" 2>&1 &

Omit the second line if the selected player or report already handles refresh. Close any manual window using the dedicated profile, then reboot:

sudo reboot

Verify the intended report loads full screen. The kiosk flag removes browser controls; it does not guarantee removal of all Power BI navigation. Use a dedicated display-friendly report or an embedded layout if application chrome must be hidden reliably.

The labwc/wtype approach follows Raspberry Pi’s official kiosk tutorial; these maintenance and restart scripts are example adaptations and must be tested on the selected image.

7. Optional: rotate two reports

In warehouse-kiosk.sh, add the second URL after the first in the Chromium command:

    chromium \
      --user-data-dir="$PROFILE" \
      --kiosk \
      --no-first-run \
      --noerrdialogs \
      "$REPORT_URL" \
      'PASTE_WAREHOUSE_MANAGEMENT_PAGE_URL_HERE'

Replace warehouse-refresh.sh with the following. Do not run an additional refresh helper alongside it:

#!/usr/bin/env bash

DWELL_SECONDS=60
PAUSE_FILE="$HOME/warehouse-maintenance"

exec 9>"$HOME/.config/warehouse-refresh.lock"
flock -n 9 || exit 0

sleep 45
while true; do
    sleep "$DWELL_SECONDS"
    if [ ! -e "$PAUSE_FILE" ]; then
        wtype -M ctrl -k Tab -m ctrl
        sleep 2
        wtype -M ctrl -k r -m ctrl
    fi
done

With exactly two tabs, each report is shown approximately every minute and reloaded approximately every two minutes. This simple variant ties reload timing to rotation; it does not independently provide a five-minute reload schedule. Use a supported player or embedded application if independent timing or seamless transitions are required. Confirm the actual interval at handoff.

Save, keep the file executable, and reboot during the maintenance window. Sign in to both reports before leaving the device unattended.

8. If manual Power BI sign-ins are unacceptable

If we need this, IT and I will choose a supported signage service or plan a private embedded application. It needs backend work and the right capacity; a browser setting alone won’t do it.

  1. Confirm internal-display licensing and production capacity. App-owns-data embedding needs appropriate capacity; ordinary browser access and user-owns-data have different viewer requirements.
  2. For an approved app-owns-data design, register a backend application/service principal and grant only the necessary workspace/report access.
  3. Store credentials or certificates securely on the backend, never in the Pi’s URL or browser source.
  4. Authorize the display device to a private HTTPS player. Protect token endpoints; network reachability alone is insufficient authorization.
  5. Obtain fresh Entra and embed tokens as required; scope tokens to the necessary content and identities.
  6. Use the Power BI JavaScript SDK to renew access with setAccessToken before expiration. The accessTokenProvider automatic hook is specifically for the supported user-owns-data scenario; do not assume it renews app-owns-data tokens.
  7. Handle retry, expired tokens, reboot, network recovery, report/page rotation, and stale-data indication.
  8. Test loss and restoration of authentication and connectivity. Assign credential rotation and backend support ownership.

Point the Pi launcher to the private player URL and remove the keyboard refresh helper if the player controls refresh and rotation. Tokens still expire; the application renews them. Capacity requirements · Embed tokens · Token renewal API.

9. Support, maintenance, and recovery

Remote management from my laptop

IT will provide screen sharing into the same desktop shown on the TV, plus key-based SSH if we use scripts. We’ll confirm company-network/VPN access, the approved account and configuration permissions, safe restart rights, and reconnecting after a reboot. My remote-management walkthrough covers the actual workflow; the IT request lists what needs enabling.

Desktop autostart keeps refresh running independently of my laptop. I won’t rely on a process left running in an SSH session. Actual addresses and account details belong in the private IT ticket.

Pause the reference scripts

touch "$HOME/warehouse-maintenance"

Then close Chromium with Alt+F4. The launcher waits while this file exists, and the helper stops sending keys. If needed, open the persistent profile normally to complete approved sign-in, then close it:

chromium --user-data-dir="$HOME/.config/warehouse-chromium" \
  'https://app.powerbi.com'

Resume the running launcher:

rm -f "$HOME/warehouse-maintenance"

For a safe restart, after approved maintenance:

sudo reboot

Check problems

tail -n 60 "$HOME/warehouse-kiosk.log"
tail -n 60 "$HOME/warehouse-refresh.log"
df -h
timedatectl status
  • Blank TV: check input, HDMI, power, sleep timers, and Pi output resolution.
  • Desktop only: check autologin, labwc autostart, executable permissions, and a leftover maintenance file.
  • Repeated launcher attempts: check another browser using the profile; close it before starting kiosk mode.
  • Stale report: I’ll check model refresh and source data. Reloading alone won’t bring new records into an Import model.
  • Login or access denied: involve identity support / Power BI admin. Do not weaken MFA or expose reports publicly as a workaround.
  • Network restored but page still broken: use the agreed reload/relaunch process. The reference helper retries reloads but cannot guarantee recovery from hangs or session expiry.

IT ownership after handoff

Use approved SSH/VPN or remote management, maintain OS/browser updates, back up configuration, and rotate or cap log files to prevent storage exhaustion. Avoid exposing SSH or debugging ports to the public internet. Keep credentials out of backups and support tickets. A read-only overlay image needs a deliberate maintenance and browser-profile persistence plan; do not enable it casually on a signed-in kiosk.

10. Test and hand off

  1. Run the acceptance checklist, including the right report pages, warehouse filters, and readability.
  2. Verify a known source update appears within the agreed freshness window.
  3. Test network loss/recovery, browser exit/relaunch, restart, and TV/Pi power restoration under IT supervision.
  4. Run a 48–72-hour pilot and targeted tests for token/session expiration. A policy with a longer window needs a separate test or documented limitation.
  5. Record settings, contacts, limitations, backup location, approved recovery actions, and authentication ownership.
  6. I’ll follow the daily operating guide and practice recovery with IT.
