Your part after IT setup

Own the reports and refresh mechanism on the platform IT provides.

You are the report developer, so your ownership includes the report itself, its data-refresh configuration, the display refresh mechanism, report rotation, and validation. IT supplies the Pi/TV platform, networking, startup integration, and administrator support.

Ask IT to show you, then try it yourself. Before handoff, practice checking freshness, requesting a report change, restoring the display, and contacting the correct support person.

Before IT finishes

  1. Provide report links. Open each report on your work computer, select the required page and warehouse view, and send the exact links and intended filters.
  2. Help arrange access. Grant the IT-approved identity access within your report permissions. Ask the relevant administrator for any licensing or tenant-level changes. Confirm access works on the actual Pi, not just your laptop.
  3. Set the business requirements. Specify report order, viewing duration, operating hours, and acceptable data age.
  4. Watch the acceptance tests. Confirm the correct values, full-screen display, rotation, startup, and recovery.
  5. Keep the handoff record. Save the support contacts, approved controls, and known sign-in limitations.

Do not assume that signing in with your own account is the permanent design. Ask IT which identity and method they approve for a shared warehouse display.

Your refresh mechanism: configure and maintain it

Display refresh is your implementation responsibility. Ask IT to hand over a supported player configuration screen or access to the Pi scripts, together with startup and recovery instructions.

  1. Choose native Power BI automatic page refresh where your data model and capacity support it; otherwise configure a browser/player reload interval.
  2. For the reference single-report script, edit warehouse-refresh.sh and set REFRESH_SECONDS=300 for five minutes. For the two-report example, edit DWELL_SECONDS=60; that variant reloads each report on its next turn, approximately every two minutes with two tabs.
  3. Use the reference setup instructions to create or update the helper and coordinate its autostart entry with IT. Pause automation before editing. Script edits take effect when the helper restarts; resume and use the approved reboot procedure after saving.
  4. Configure semantic-model refresh in Power BI separately. Check source credentials, refresh history, and any required gateway. Ask IT/admins for infrastructure or settings outside your permissions.
  5. Publish the intended pages, filters/bookmarks, and a source-based freshness indicator. Test that reloads retain the intended view and browser kiosk mode.
  6. Validate with a known source-data change, then test rotation, network recovery, and restart with IT.

IT retains responsibility for device policies, network access, and the kiosk platform. Ownership of refresh does not require you to change Conditional Access, licensing, or unsupported system settings.

Changing reports or refresh timing

  1. Open the proposed report on your work computer and confirm it has the right information.
  2. Update the approved player settings or Pi configuration with its link, page, filters, order, and desired duration.
  3. Use the access IT handed over. If the configuration is locked down, ask IT for the required access or have them apply your reviewed change.
  4. Make sure the display identity also has permission to view the new report.
  5. Verify it on the TV after the change and after a reload or restart.

Configure display refresh and data freshness separately. Example: reload the screen every five minutes, and configure/test the data pipeline so report data is no more than fifteen minutes old. The second requirement may need a different Power BI data connection or capacity.

Reference setup: maintenance controls

Use this section only if IT installed the scripts from the full setup guide and authorized you to use the Pi terminal. Otherwise follow their handoff procedure.

  1. Pause automatic refresh/rotation and browser relaunch:
    touch "$HOME/warehouse-maintenance"
  2. Press Alt+F4 on the Pi to close the browser. If reauthentication is needed, open the same profile in normal mode:
    chromium --user-data-dir="$HOME/.config/warehouse-chromium" \
  'https://app.powerbi.com'
  3. Complete only the approved sign-in and close that normal browser window.
  4. Remove the pause file; the running launcher will reopen kiosk mode:
    rm -f "$HOME/warehouse-maintenance"

The pause file survives a reboot. If the Pi starts to the desktop instead of the report after maintenance, ask IT to check whether it was left in place.

Message to report an issue

Warehouse display issue at [location / asset name]. At [time and time zone], the screen showed [exact message or behavior]. Report: [name and page]. “Data as of”: [timestamp]. Expected: [correct view or freshness]. I tried [approved action] and the result was [result]. Please check [device / access / report refresh].

Include a photo only if workplace rules permit it and the destination is approved for the report’s information. Never send passwords or MFA codes.
